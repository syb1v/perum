## 1. DNS-архитектура: отказ от wildcard → per-school A-records

### Текущее состояние
- Wildcard DNS (`*.domain → IP`) **удалён** из всех зон
- Каждая школа получает индивидуальную A-запись `school.domain → node_ip`
- Записи создаются при провижининге школы, удаляются при purge

### Проблемы (найдено при анализе)

| Проблема | Серьёзность | Решение |
|----------|-------------|---------|
| DNS не обновляется при suspend/unsuspend | Средняя | Добавить вызов `_sync_school_dns` в lifecycle-хуки |
| DNS не чистится при archive (без purge) | Средняя | Вызывать `_delete_school_dns` при archive |
| DNS не обновляется при смене IP ноды | Низкая | Добавить в `node_planner` или ручной re-sync |
| Нет авто-синхронизации — только ручная кнопка | Низкая | Добавить фоновый sweep раз в N минут |
| Org_admin не видит DNS-статус школ | Средняя | Добавить колонку в таблицу школ |
| Org_admin не может запустить sync | Средняя | Добавить кнопку «Синхр. DNS» в кабинет орг |
| Нет возможности задать cf_zone_id после создания орг | Низкая | Добавить поле в edit-форму организации |

### Микро-реархитектура: многонодовые организации

**Проблема:** организация может иметь несколько нод. Школы распределяются по нодам автоматически (NodePlanner). Но:
- Лендинг орг живёт на одной «первичной» ноде (`Organization.node_id`)
- `_refresh_org_landing` отправляет ВСЕ school_hosts на эту ноду — некорректно для школ на других нодах

**Предлагаемое решение:**
1. **Первичная нода** (`Organization.node_id`) — обязательна, держит лендинг
2. **Вторичные ноды** — только для школ, без лендинга
3. **DNS для школ** — A-запись `school.domain → IP_ноды_школы` (уже реализовано)
4. **Лендинг** — показывает список школ с их URL (без знания, на какой ноде школа)
5. **Выбор ноды при создании** — `NodePlanner.find_best_node` с учётом:
   - Доступной ёмкости
   - Предпочтения выделенных нод перед pool-нодами
   - (Опционально) ручной выбор ноды org_admin'ом

**API-изменения:**
- `POST /api/schools` — добавить опциональный `node_id` (ручной выбор ноды)
- `POST /api/schools/{id}/move-node` — перемещение школы на другую ноду
- `GET /api/organizations/{id}/dns` — доступно org_admin (сейчас только platform_admin)

## 4. Биллинг и тарификация

### Текущая модель
| План | Школ | Цена | Особенности |
|------|------|------|-------------|
| Trial | 1 | 0 ₽ | 14 дней, базовая аналитика |
| Basic | 5 | 1 990 ₽/мес | Стандартный функционал |
| Pro | 20 | 4 990 ₽/мес | Расширенная аналитика, приоритетная поддержка |
| Enterprise | ∞ | Договорная | Выделенные ноды, брендирование |

**Проблемы текущей модели:**
- Привязка к количеству школ не отражает реальную нагрузку (школа на 50 учеников и на 2000 стоят одинаково)
- Нет гибкости для маленьких организаций (1-2 школы)
- Enterprise «договорная» — слишком размыто, нет понятных критериев
- Нет годовой скидки (стандарт для B2B)

---

### Вариант 1: Доступ + школы (упрощённый)
*Минимальные изменения, ближе всего к текущей модели.*

| План | Мес / Год | Школ | Учеников | Ключевое отличие |
|------|-----------|------|----------|-----------------|
| Trial | 0 ₽ | 1 | до 100 | 14 дней, базовая аналитика |
| Starter | 990 / 9 900 ₽ | 2 | до 500 | Базовый функционал, email-поддержка |
| Growth | 2 990 / 29 900 ₽ | 10 | до 3 000 | Аналитика, кастомный домен, приоритетная поддержка |
| Pro | 5 990 / 59 900 ₽ | 30 | до 10 000 | Всё + выделенная нода, брендирование, API |
| Enterprise | от 14 990 ₽ | ∞ | ∞ | Выделенный кластер, SLA, персональный менеджер |

**Плюсы:** просто объяснить, легко считать, годовая скидка ~17% (1 месяц бесплатно).
**Минусы:** не учитывает неравномерность нагрузки, крупные школы всё ещё «дешёвые».

---

### Вариант 2: Per-ученик (справедливый)
*Плата за активных учеников — отражает реальную нагрузку.*

| План | Базовый платёж | Учеников вкл. | Сверх ученика | Особенности |
|------|---------------|---------------|---------------|-------------|
| Trial | 0 ₽ | — | — | 14 дней, до 50 учеников |
| Starter | 490 ₽/мес | 100 | +5 ₽/уч/мес | Базовый функционал |
| Growth | 1 490 ₽/мес | 500 | +3 ₽/уч/мес | Аналитика, домены, поддержка |
| Pro | 3 990 ₽/мес | 2 000 | +2 ₽/уч/мес | Всё + выделенная нода, API |

**Пример расчёта (Growth):**
- Школа на 300 учеников: 1 490 ₽ (500 вкл.) → **1 490 ₽/мес**
- Сеть из 3 школ, суммарно 2 000 учеников: 1 490 + 3×500 = 2 990 ₽/мес
- Крупная орг, 8 000 учеников: 3 990 + 6 000×2 = **15 990 ₽/мес**

**Плюсы:** справедливо (маленькие платят мало), масштабируется, стимулирует рост.
**Минусы:** сложнее посчитать «на глаз», нужен учёт активных учеников.

---

### Вариант 3: Гибридный (школы + ученики + ноды)
*Комбинация: базовый платёж за платформу + доплаты за школы/учеников/ноды.*

**Базовый платёж (обязателен):** 990 ₽/мес — доступ к платформе, до 2 школ, до 200 учеников, 1 нода.

**Доплаты (опционально):**

| Ресурс | Единица | Цена |
|--------|---------|------|
| Доп. школа | 1 школа | +290 ₽/мес |
| Доп. ученики | пакет 500 | +490 ₽/мес |
| Доп. нода | 1 нода | +990 ₽/мес |
| Выделенная нода | 1 сервер | +2 990 ₽/мес |
| Брендирование | white label | +1 990 ₽/мес |
| SLA 99.9% | договор | +30% к счёту |

**Примеры:**
- Маленькая орг (1 школа, 150 уч.): **990 ₽/мес**
- Средняя (5 школ, 1 200 уч., 1 нода): 990 + 3×290 + 2×490 = **2 840 ₽/мес**
- Крупная (20 школ, 8 000 уч., 3 ноды, бренд): 990 + 18×290 + 16×490 + 2×990 + 1 990 = **17 030 ₽/мес**

**Плюсы:** максимальная гибкость, клиент платит только за то что использует, легко upsell.
**Минусы:** клиенту сложнее понять итоговую цену, больше переменных для биллинг-движка.

## 5. CDN для работы в белых списках

### Проблема
Школы часто сидят за прокси с белыми списками доменов. Нужен единый домен для статики, API и WebSocket.

### Решение
- **Cloudflare CDN** (бесплатный план):
  - Кеширование статики Next.js (`/_next/static/*`)
  - Единый IP для API (проксирование через CF)
  - WebSocket через CF (поддерживается на всех планах)
- **Альтернатива:** собственный nginx на выделенном IP как reverse proxy cache

### Риски
- CF в России может быть замедлен/заблокирован
- Нужен fallback на прямой IP для российских школ
