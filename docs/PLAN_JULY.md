## 1. DNS-архитектура: отказ от wildcard → per-school A-records

### Текущее состояние
- Wildcard DNS (`*.domain → IP`) **удалён** из всех зон
- Каждая школа получает индивидуальную A-запись `school.domain → node_ip`
- Записи создаются при провижининге школы, удаляются при purge

### Проблемы (найдено при анализе)

| Проблема | Серьёзность | Решение |
|----------|-------------|---------|
| DNS не обновляется при suspend/unsuspend | Средняя | Добавить вызов `_sync_school_dns` в lifecycle-хуки |
| DNS не чистится при archive (без purge) | Средняя | Вызывать `_delete_school_dns` при archive |
| DNS не обновляется при смене IP ноды | Низкая | Добавить в `node_planner` или ручной re-sync |
| Нет авто-синхронизации — только ручная кнопка | Низкая | Добавить фоновый sweep раз в N минут |
| Org_admin не видит DNS-статус школ | Средняя | Добавить колонку в таблицу школ |
| Org_admin не может запустить sync | Средняя | Добавить кнопку «Синхр. DNS» в кабинет орг |
| Нет возможности задать cf_zone_id после создания орг | Низкая | Добавить поле в edit-форму организации |

### Микро-реархитектура: многонодовые организации

**Проблема:** организация может иметь несколько нод. Школы распределяются по нодам автоматически (NodePlanner). Но:
- Лендинг орг живёт на одной «первичной» ноде (`Organization.node_id`)
- `_refresh_org_landing` отправляет ВСЕ school_hosts на эту ноду — некорректно для школ на других нодах

**Предлагаемое решение:**
1. **Первичная нода** (`Organization.node_id`) — обязательна, держит лендинг
2. **Вторичные ноды** — только для школ, без лендинга
3. **DNS для школ** — A-запись `school.domain → IP_ноды_школы` (уже реализовано)
4. **Лендинг** — показывает список школ с их URL (без знания, на какой ноде школа)
5. **Выбор ноды при создании** — `NodePlanner.find_best_node` с учётом:
   - Доступной ёмкости
   - Предпочтения выделенных нод перед pool-нодами
   - (Опционально) ручной выбор ноды org_admin'ом

**API-изменения:**
- `POST /api/schools` — добавить опциональный `node_id` (ручной выбор ноды)
- `POST /api/schools/{id}/move-node` — перемещение школы на другую ноду
- `GET /api/organizations/{id}/dns` — доступно org_admin (сейчас только platform_admin)

## 5. CDN для работы в белых списках

### Проблема
Школы часто сидят за прокси с белыми списками доменов. Нужен единый домен для статики, API и WebSocket.

### Решение
- **Cloudflare CDN** (бесплатный план):
  - Кеширование статики Next.js (`/_next/static/*`)
  - Единый IP для API (проксирование через CF)
  - WebSocket через CF (поддерживается на всех планах)
- **Альтернатива:** собственный nginx на выделенном IP как reverse proxy cache

### Риски
- CF в России может быть замедлен/заблокирован
- Нужен fallback на прямой IP для российских школ

### 6.2. Учитель

| Приоритет | Функция | Детали |
|-----------|---------|--------|
| **P1** | Выставить ДЗ | Форма: предмет, класс, дата сдачи, описание, вложения. Авто-нотификация ученикам и родителям. |
| **P1** | Привязать тему к оценкам (batch) | **Ключевое требование:** учитель вводит тему ОДИН раз — и она автоматом проставляется всем ученикам класса за эту дату/урок.
